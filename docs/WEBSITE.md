# glaze-os.com

The project website is a static page in `site/`: `index.html`, `style.css`,
`unlock.js` (the hero's slide to unlock), `404.html`, Bitstream Vera from
`assets/fonts`, and images in `site/img`. It needs no build step to preview:

```
python3 -m http.server --directory site 8000
```

## Images

Everything on the device screens is a real Glaze screenshot. `tools/mksite.py`
builds `site/img` from the final screens of scripted runs (`tests/run.sh`
writes `out/shots/<name>.png`); its header lists the runs to capture. It also
needs the device frame artwork from the be300 repository
(`src/ui/assets/be300_frame.png`), and Pillow:

```
tools/mksite.py out/shots ../be300/src/ui/assets/be300_frame.png
```

The hero's lock screen is split into layers so the page can move the knob:
the screen with an empty track, the knob, the label and the label's mask
(for the shimmer). The empty track comes from `t_site_lockmid.txt` and
`t_site_lockdrag.txt`, which hold the knob at two places with the label faded.
The script checks it against both frames pixel for pixel. The track geometry
is SpringBoard's (`servers/springboard/sb_internal.h`); if it changes, update
`tools/mksite.py`, `site/style.css` and `site/unlock.js` together.

The October 21, 2026 feature update adds these real 240×320 emulator captures.
They are supplemental to the original gallery generated by `mksite.py`:

See `docs/TASK_MANAGER.md` and `docs/WINCE.md` for the capture commands and
prerequisites. Copy each PNG to its website image name; convert BMP captures
without resizing, for example with `sips -s format png <capture.bmp> --out
site/img/<name>.png` on macOS. Keep application executable files, DLLs and NAND
images out of `site/`. The compatibility screenshots show locally imported apps;
the website does not distribute the vendor software.

The update covers changes since the original website commit `81253d0`, whose
HTML matched the live page before publication. It includes Task Manager, AIM,
selected original WinCE apps, shared list behavior, graphics/text/flash
performance improvements, demand-paged romfs and developer benchmarks. The
hardware overview also documents the existing Stowaway keyboard support.

The emulator button uses
`https://linux4be.com/?image=glaze&boot=1&card=none&keyboard=0` to start Glaze
directly, without requiring the network bridge or a physical keyboard.
URL configuration and validation are documented in the be300 repository's
`web/README.md`. Deploy emulator URL support before publishing a page that
links to it. Browser sound starts after the first user interaction.

## Infrastructure

`infra/site/stack.json` defines the `glaze-os-site` CloudFormation stack, in
**us-east-1** because CloudFront needs its certificate there. It follows the
App Store's stack (`docs/APP_STORE_AWS.md`):

- `glaze-os-site-<account-id>-us-east-1`: encrypted, versioned S3 storage with
  public access blocked. Old object versions expire after 90 days. The bucket
  is retained if the stack is deleted.
- A CloudFront distribution with Origin Access Control, HTTP/2 and HTTP/3,
  compression, TLS 1.2 or later, and AWS's managed security-headers policy.
  It uses the managed CachingOptimized policy, which honours the objects'
  `Cache-Control`.
- A CloudFront Function that redirects `www.glaze-os.com` to the apex and
  serves `index.html` for directory URLs. Missing pages get `404.html`.
- One DNS-validated certificate for `glaze-os.com` and `www.glaze-os.com`, and
  A/AAAA alias records for both in the existing `glaze-os.com` zone.

The stack doesn't touch the App Store's `appstore.glaze-os.com` records.

```
aws --profile linux4be cloudformation deploy \
  --region us-east-1 --stack-name glaze-os-site \
  --template-file infra/site/stack.json \
  --parameter-overrides \
    HostedZoneId=Z0787879KYK5LHIR1IDN \
    DomainName=glaze-os.com \
  --no-fail-on-empty-changeset
```

Use `--no-execute-changeset` first to review a change set before applying it.
Certificate validation and the CloudFront deployment take several minutes.

## Publish

### October 25 hardware update and downloads

The page covers GlazeBoot, physical-device boot/storage/network/audio results,
master volume, Wi-Fi capabilities, SomaFM, Gmail, console packages,
multitasking, touch/display controls and Browser scripting/frames. The hardware
table separates observed real-device results from emulator-only security
coverage and incomplete WL54-CF physical interoperability. Existing gallery
images remain real emulator captures, not hardware photographs.

The release ZIP contains a `Glaze/` boot folder and `Emulator/glaze.bin`, plus
setup instructions, per-file checksums, source links and license notices.
`site/downloads/latest.json` and the external SHA-256 file are tracked; ZIPs
are generated and ignored. The full hardware archive includes every built-in
app (`GB_APPS=all`) and the unmodified, pinned Linux CF8385 firmware under
`firmware/LICENCE.Marvell`. Its exact source and hashes are included in the ZIP.
Only the approved helper/main pair may ship; the different CAB-derived helper
is rejected. Physical interoperability of the Linux pair is not yet validated.
The public emulator NAND excludes Marvell firmware because its license permits
use only with Marvell silicon. Both images omit shared Wi-Fi seeds.
`prepare-card.py` generates a private per-card seed locally and preserves an
existing one. See [WL54CF.md](WL54CF.md) for licensing and provenance.

To reproduce the release from the advertised source revision (currently
`e4500c1204252cdf37bc8dfd86e8e678bc7b641a`):

```sh
python3 tools/fetch_wl54cf_firmware.py
# Force romfs regeneration when switching firmware build options.
./build.sh all INIT=bin/springboard INPUT_SCRIPT= WL54CF=0 BUILD_ID=e4500c1 -W tools/mkromfs.py
./build.sh glazeboot INIT=bin/springboard INPUT_SCRIPT= WL54CF=1 GB_APPS=all BUILD_ID=e4500c1
make glazeboot-exe BE300_DEV=/path/to/be300-dev
mkdir -p out/public-release
cp out/glazeboot/GlazeBoot.exe out/glazeboot/kernel.bin out/glazeboot/romfs.img out/glazeboot/glaze.cfg out/public-release/
make -C host mkfsimg
# A public emulator image must not distribute a shared WPA entropy seed.
host/mkfsimg userdata 704 out/public-release/fs.img
python3 tools/mk_nand.py --kernel out/kernel.elf --spl out/spl.elf \
  --romfs out/romfs.img --fs-image out/public-release/fs.img --out out/public-release/glaze.bin
python3 tools/package_glazeboot.py --build-dir out/public-release \
  --revision e4500c1204252cdf37bc8dfd86e8e678bc7b641a --date 2026-10-25
python3 tests/site_release.py
```

The fetcher, firmware manifest/license and packaging tool are part of the
website update. When rebuilding an older advertised OS revision, retain
`tools/fetch_wl54cf_firmware.py`, `tools/package_glazeboot.py`, `firmware/` and
these instructions from the release tooling revision separately. `SOURCE.txt`
and `latest.json` link both exact source revisions. Use fresh build output
for public releases, with no locally imported Windows CE apps or personal
files. Update the download links and source revision in `site/index.html`
when preparing a new release. The full-app/firmware release uses a new
`-full.zip` URL; the earlier reduced-app ZIP remains available at its original URL.

The publisher refuses a missing ZIP, size/hash mismatch or incorrect checksum
file before making AWS calls. It uploads downloads before HTML, retains old
versioned downloads, and checks the public ZIP, MIME type, checksum and release
metadata after publication. `tests/site_release.py` covers these safeguards,
approved firmware inclusion with its license, rejection of altered firmware,
all built-in apps, emulator firmware exclusion, per-file hashes and private seed setup.

```
python3 tools/publish_site.py --profile linux4be --dry-run
python3 tools/publish_site.py --profile linux4be
```

The publisher reads the bucket and distribution from the stack's outputs. It
uploads assets with `Cache-Control: public, max-age=3600` and then the HTML
with `no-cache`, deleting files no longer in `site/`. It then invalidates the
distribution and checks the live site:
- the pages and frame image match `site/`
- missing pages get the 404 page
- `www` and plain HTTP redirect to `https://glaze-os.com`
- the bucket refuses anonymous reads
- the download ZIP, SHA-256 file and release metadata match the local build

`--verify-only` repeats the checks without uploading.
